# Security Policy

## Reporting a vulnerability

Do not open a public issue for a vulnerability that could expose users or repositories. Use GitHub private vulnerability reporting when available. Otherwise, contact the maintainer privately through the address listed on their GitHub profile.

Include the affected revision, impact, minimal reproduction, and suggested mitigation. Do not include real secrets, personal data, or third-party source code.

## Scope

Reports about unsafe tool execution, command injection, unintended network access or source upload, secret disclosure, and installer path handling are especially welcome. Security support applies to the latest released version.
